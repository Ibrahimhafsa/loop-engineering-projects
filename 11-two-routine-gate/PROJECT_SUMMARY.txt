WHAT WAS BUILT
================================================================================

A Complete Two-Routine System with Human Approval Gate

Workflow:
  1. Routine A (Manual Trigger)
     → Creates a draft proposal
     → Saves to draft_latest.md
     → Records in state.json
     → Does NOT automatically proceed to B

  2. Human Gate (Explicit Approval)
     → Human reads draft
     → Uses approve_draft.py to approve/reject
     → Decision recorded in state.json
     → Approval must be explicit

  3. Routine B (Only After Approval)
     → Starts as HTTP API server (localhost:9999)
     → Requires bearer token for authentication
     → Checks approval status in state.json
     → Only executes if approved
     → Creates result_approved.md
     → Records execution in state.json

Security Features:
  ✓ Bearer token authentication (no hardcoded secrets)
  ✓ Token protected from Git (.gitignore)
  ✓ No external APIs or credentials
  ✓ Full audit trail in state.json
  ✓ Approval gate blocks unauthorized execution
  ✓ Python standard library only (zero external packages)

INTERVIEW EXPLANATION
================================================================================

Use this 60-second explanation for interviews:

"I built two routines connected by a human approval gate. Routine A creates a
draft—like a proposal. Instead of automatically proceeding, the system stops
and waits for me, the human, to review the draft. If I approve it, then
Routine B runs—it's an HTTP server that executes the approved action.

The key security features are:
1. A bearer token that proves you're authorized
2. Checking that the draft was actually approved before allowing Routine B to run
3. A state file that logs every action for audit purposes
4. No secrets in Git—tokens are protected locally

This pattern prevents automation from running the wrong thing without human
oversight. Real-world systems use this in CI/CD pipelines, change management,
and automated workflows."
