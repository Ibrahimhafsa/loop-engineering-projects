## Key Concepts Quick Reference

### Routine Rehearsal
The practice of testing a routine manually (one-off) before putting it on a repeating schedule. Catches problems that status columns miss.

### One-Off Run
A single, manual execution of a routine specifically for testing and validation. Not on a repeating schedule. The place where you inspect the full transcript.

### Full Transcript
The complete output of a routine execution, including all status messages, file operations, data processing, and any errors. More informative than the status column alone.

### Status Column
Simple indicator (GREEN/RED or SUCCESS/FAILED) that shows whether the process exited cleanly. Does not indicate whether the task actually succeeded.

### A1, A3, A5 Levels
- **A1** (Projects 1-2): Basic agentic loops with low autonomy
- **A3** (Projects 3-7): Intermediate loops with decision-making
- **A5** (Projects 8-9): Advanced loops with safety and validation

### Silent Failure
When a routine exits with status GREEN but doesn't complete its task correctly. The status column alone would be misleading. Full transcript reveals the actual problem.

## FAQ

**Q: Do I need to run both routines?**  
A: Yes. Run the successful one first (routine.py), then the failing one (routine_failing.py) to understand the difference.

**Q: What if I don't see the full transcript?**  
A: Check the TEST_RESULTS.md file - it has the complete transcripts from the actual runs.

**Q: Can I modify the routines?**  
A: Yes! Try modifying routine.py to do something different, then test it with one-off runs before scheduling.

**Q: What does "rehearsal" mean exactly?**  
A: Testing manually first (one-off run) before putting it on a schedule. Just like a theater rehearsal before opening night.

**Q: Why is Project 9 at A5 level?**  
A: Because it teaches production-readiness concepts - validation, verification, and safe deployment practices.
