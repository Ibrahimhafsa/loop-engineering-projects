================================================================================
  THE CRITICAL LESSON
================================================================================

"Green means the session ended without an infrastructure error;
it does not necessarily mean the task itself succeeded."

WHY STATUS ALONE IS INSUFFICIENT:
─────────────────────────────────

A routine can show STATUS: GREEN but actually:
    ✗ Produce wrong output
    ✗ Process corrupted data
    ✗ Skip critical steps silently
    ✗ Generate empty files
    ✗ Write to wrong location
    ✗ Process only partial data
    ✗ Have permission issues on retry
    ✗ Depend on external state that changed

THE SOLUTION:
─────────────

BEFORE putting a routine on a repeating schedule:
    1. Run it manually (one-off)
    2. Read the FULL transcript from start to finish
    3. Verify output files were created
    4. Check that the actual data is correct
    5. Test edge cases or error conditions
    6. ONLY THEN schedule it

Full Transcript Shows:
    ✓ Exactly what happened at each step
    ✓ What files were created or modified
    ✓ What data was processed
    ✓ Any warnings or anomalies
    ✓ Actual success, not just infrastructure success

Status Column Shows:
    → Only whether process exited cleanly
    → Only the exit code
    → Nothing about what actually happened

================================================================================
  EXPLANATION FOR INTERVIEW (Beginner Level)
================================================================================

"In this project, I learned about routine rehearsal. Before you put an
automated routine on a schedule (like every hour or every day), you need to
test it first manually. I created a simple routine that summarizes recent
git commits and saves them to a file.

First, I ran it manually and read the complete output (the transcript), not
just the green 'success' status. This let me verify that the file was actually
created and had the right data.

Then I created a version that intentionally fails to show that a routine can
appear successful (green status) but actually fail at its task. I learned that
a green status only means the process exited cleanly - it doesn't mean the
task actually succeeded.

The key lesson is: Before scheduling anything, you must rehearse it with a
manual run and read the full transcript to verify both that the process ran
cleanly AND that the actual task succeeded. The status column alone is not
enough.

This project also taught me about A1, A3, and A5 - these are different levels
of automation in the course. Project 9 is at the A5 level because it teaches
you to validate and be safe before going into production."
