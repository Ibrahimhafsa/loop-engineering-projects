PROOF: HOW LIMIT PREVENTS DOOM LOOPS
=====================================
Without limit:
  target = 10, increment = 1
  Beat 1-10: value reaches 10 (if possible)
  Beat 11-∞: INFINITE LOOP (DOOM LOOP)
  CPU: 100%, System: CRASH

With limit (our implementation):
  target = 10, increment = 1, max_attempts = 5
  Beat 1-5: value reaches 5
  After beat 5: Loop STOPS (5 >= 5 limit check)
  Result: Graceful exit in 2 seconds, system safe

PROOF: HOW SPINE PROVIDES MEMORY
=================================
Run 1: progress.md created (3 attempts, value=3)
Run 2: progress.md updated (5 attempts, value=5)
Run 3: progress.md read (sees value=5, recognizes 5>=3=success)
       No new attempts needed, uses existing knowledge

BEGINNER EXPLANATION
====================
Loop: Do something repeatedly until success or max attempts
Beat: One cycle of the loop (one "heartbeat")
Success Condition: "Stop when value reaches target"
Limit: "Never do more than 5 attempts"
Spine: "Remember what happened in previous runs"
Safe Loop: Loop with success condition + limit + spine

KEY INSIGHT
===========
A safe loop has THREE protections:
1. Goal (success condition) - knows when to stop
2. Safety (limit) - can't run forever
3. Memory (spine) - learns from the past

This makes it SAFE to run without supervision.

INTERVIEW READY
===============
This project is simple enough to explain in a job interview:

"I built a safe loop that tries to reach a target value. It has:
- A clear goal (success condition)
- A limit to prevent infinite loops (doom loop prevention)
- A memory file (spine) that remembers previous attempts

The loop repeatedly increments a counter until either:
1. It reaches the target (success)
2. It uses all 5 attempts (limit reached)

learns from the past. On the next run, it can recognize success from
previous attempts."

TROUBLESHOOTING
===============
Q: "progress.md not created"
A: Run the script once: python safe_loop.py 3

Q: "Why does Run 3 use previous attempts?"
A: The loop reads progress.md at startup and recognizes the
   current value (5) already exceeds the target (3)

Q: "Can I change the limit?"
A: Yes, modify: run_safe_loop(target=target, max_attempts=10)

Q: "Can I change the increment?"
A: Yes, in perform_beat(), change: progress["current_value"] += 1
